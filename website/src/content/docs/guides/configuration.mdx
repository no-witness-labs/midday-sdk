Midday SDK comes with pre-configured network settings for common environments.

### Built-in Networks

### Blockfrost-Hosted Networks

Midnight retired its own mainnet endpoints on 2026-09-30 and its Preprod
endpoints on 2026-10-09; both networks are now served by
[Blockfrost](https://blockfrost.io). `Config.blockfrost(network, projectId)`
builds the indexer, WebSocket and RPC URLs with the token as a `project_id`
query parameter, and `Config.getNetworkConfig('preprod')` throws with a pointer
to it.

:::caution
The token is part of every URL. Keep it server-side: read it from an
environment variable, never bundle it into browser code, and mask it in logs
with `Config.redactUrl(text)`. Tokens are network-specific.
:::

### Custom Network

For custom deployments, provide the full network configuration:

```typescript
const client = await Midday.Client.create({
  networkConfig: {
    networkId: 'testnet',
    indexer: 'https://indexer.testnet.midnight.network/graphql',
    indexerWS: 'wss://indexer.testnet.midnight.network/graphql/ws',
    node: 'wss://node.testnet.midnight.network',
    proofServer: 'https://proof.testnet.midnight.network',
  },
  seed: 'your-64-char-hex-seed',
  privateStateProvider: Midday.PrivateState.inMemoryPrivateStateProvider(),
});
```

## ZK Configuration (Per-Contract)

Each contract has its own zk circuits. zkConfig is loaded when you load a contract, not at client creation.

### From Path (Node.js)

```typescript
const loaded = await client.loadContract({
  module: CounterContract,
  zkConfig: Midday.ZkConfig.fromPath('./contracts/counter'),
  privateStateId: 'my-counter',
});
```

### From URL (Browser)

```typescript
const loaded = await client.loadContract({
  module: CounterContract,
  zkConfig: new Midday.ZkConfig.HttpZkConfigProvider('https://cdn.example.com/zk'),
  privateStateId: 'my-counter',
});
```

## Private State Provider

Private state stores contract-specific secrets that should never leave the client.

### In-Memory (Development)

```typescript
const privateStateProvider = Midday.PrivateState.inMemoryPrivateStateProvider();
```

### IndexedDB (Browser)

```typescript
// Encrypted (AES-GCM, PBKDF2) and scoped per account and per contract.
// IndexedDB in browsers, LevelDB on disk in Node.
const privateStateProvider = Midday.PrivateState.persistentPrivateStateProvider({
  accountId: wallet.addresses.unshielded,
  password: () => promptForPrivateStatePassword(), // ≥ 16 characters, never derived from public data
});
```

## Wallet Configuration

### Seed-Based (Node.js)

For server-side applications, provide a 64-character hex seed:

```typescript
const client = await Midday.Client.create({
  networkConfig: Midday.Config.NETWORKS.preview,
  seed: 'your-64-char-hex-seed', // 32 bytes as hex
  privateStateProvider: Midday.PrivateState.inMemoryPrivateStateProvider(),
});
```

:::caution
Never commit seeds to version control. Use environment variables or secure secret management.
:::

### Wallet Factories

The SDK provides convenient wallet factories:

```typescript
// From seed (Node.js) — positional args
const wallet = await Midday.Wallet.fromSeed(seed, networkConfig);

// From browser (Lace extension)
const wallet = await Midday.Wallet.fromBrowser('preview');

// Reading contracts without a wallet: Midday.Client.createReadonly()
```

### Persisting Seed Wallet State

A seed wallet normally syncs from genesis on every start, which can take hours on
public networks. Long-running services can snapshot the synced state and resume
from it after a restart:

```typescript
import { writeFile, readFile } from 'node:fs/promises';

// Snapshot (e.g. periodically, and before shutdown)
const wallet = await Midday.Wallet.fromSeed(seed, networkConfig);
const snapshot = await wallet.serializeState();
await writeFile('wallet-state.enc', encrypt(snapshot)); // your encryption
await wallet.close();

// Resume: only the blocks since the snapshot are synced
const saved = decrypt(await readFile('wallet-state.enc'));
const resumed = await Midday.Wallet.fromSeed(seed, networkConfig, { restoreState: saved });
```

The snapshot is a versioned JSON string that records the snapshot format version,
the `networkId`, and the wallet SDK package versions that produced it, alongside
the shielded, unshielded and DUST wallet states and the transaction history.

Restoring validates the snapshot first and fails with `WalletSnapshotError` instead
of silently syncing from scratch. Decide in your code whether to discard the
snapshot and resync:

```typescript
const wallet = await Midday.Wallet.fromSeed(seed, networkConfig, { restoreState: saved })
  .catch(async (err) => {
    if (err?._tag !== 'WalletSnapshotError') throw err;
    // err.reason: 'malformed' | 'unsupported-version' | 'network-mismatch'
    //           | 'key-mismatch' | 'restore-failed'
    return Midday.Wallet.fromSeed(seed, networkConfig); // full resync
  });
```

`serializeState()` fails with reason `'pending-transactions'` while submitted
transactions are still unconfirmed, because pending submissions are not part of
the snapshot. Retry once they settle. It is only available on seed-backed wallets.
Effect users can call `wallet.effect.serializeState()`.

:::danger[Snapshots contain private wallet data]
A snapshot holds your coins, UTXOs, nullifier-related data and transaction history.
It does not contain the seed or secret keys, but anyone who reads it learns your
private balances and activity. Store snapshots encrypted and access-controlled,
treat them like the seed, and never log their contents.
:::

### Lace Wallet (Browser)

For browser applications, connect to the Lace wallet extension:

```typescript
const wallet = await Midday.Wallet.fromBrowser('preview');
const client = await Midday.Client.create({
  wallet,
  privateStateProvider: Midday.PrivateState.persistentPrivateStateProvider({
    accountId: wallet.addresses.unshielded,
    password: () => promptForPrivateStatePassword(), // ≥ 16 chars, never public data
  }),
});
```

See the [Browser Usage](/midday-sdk/guides/browser-usage/) guide for more details.

### Fee Relay

For browser apps where users don't need to hold dust tokens:

```typescript
const client = await Midday.Client.create({
  wallet,
  privateStateProvider: Midday.PrivateState.persistentPrivateStateProvider({
    accountId: wallet.addresses.unshielded,
    password: () => promptForPrivateStatePassword(), // ≥ 16 chars, never public data
  }),
  feeRelay: { url: 'http://localhost:3002' },
});
```
